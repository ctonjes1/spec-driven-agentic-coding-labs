Module 8 Requirements to Vendor Traceability Validator

Python automation and compliance tooling

45–60 minute labsClaude Code and CodexEvidence required
Specification gate: finish and freeze SPEC.md and its acceptance criteria before creating implementation files.

Objective

Reconcile requirements and vendor responses while refusing to count unsupported compliance assertions as demonstrated coverage.

Human judgment

Explain why a complete crosswalk does not establish that a proposed solution actually meets a requirement.

Constraints

  1. Python standard library only
  2. Inputs remain unchanged
  3. Metrics use documented denominators
  4. CSV exports must neutralize formula injection

Threat and failure assumptions

  1. Duplicate responses inflate coverage
  2. Narrative claims lack evidence
  3. Mandatory requirements disappear from the denominator
  4. Spreadsheet formulas execute when exported

Frozen contract

Write these numbered requirements into SPEC.md. Add exact schemas, reason codes, precedence, error behavior, trust boundaries, and requirement-to-test traceability. Mark the reviewed contract SPEC STATUS: FROZEN and SPEC VERSION: 1.0.

  1. R1 Validate unique requirement and response identifiers
  2. R2 Classify mandatory, optional, supported, unsupported, and conflicting responses
  3. R3 Require evidence references before counting demonstrated coverage
  4. R4 Calculate denominators and percentages deterministically
  5. R5 Treat missing mandatory responses as blockers
  6. R6 Escape dangerous CSV cell prefixes
  7. R7 Hash inputs and produce a sorted report

Acceptance criteria

  1. Supported response with evidence counts
  2. Unsupported assertion does not count
  3. Missing mandatory item is a blocker
  4. Duplicate response invalidates input
  5. Conflicting responses are flagged
  6. Independent metric recomputation matches
  7. CSV formula prefix is neutralized
  8. Input hashes remain unchanged

Implementation checkpoints

TimeRequired activity
0–12 minutesClaude Code drafts SPEC.md and acceptance criteria. Codex challenges ambiguity, unsafe defaults, precedence, and unverifiable claims. The learner resolves findings and freezes version 1.0. No implementation files exist yet.
12–23 minutesCodex derives black-box tests from the frozen contract and captures the expected failing run. Claude Code identifies contradictions without silently rewriting tests or requirements.
23–41 minutesClaude Code implements only frozen requirements and updates the requirement-linked change ledger. Preserve the complete test output.
41–53 minutesCodex reviews the diff against SPEC.md, reruns tests independently, exercises the adversarial path, and inspects logs, errors, dependencies, and state transitions.
53–60 minutesThe learner records the human disposition, remaining assumptions, production gaps, and an evidence-bounded completion statement.

Required adversarial or failure-path test

Provide a vendor response beginning with =HYPERLINK(...), mark it fully compliant, and omit evidence. The response must not count as demonstrated coverage and the CSV export must not execute a formula.

Evidence package

Module-specific evidence: Independent metric check, missing-mandatory tests, duplicate result, CSV-injection test, and unchanged input hashes.

Also submit SPEC.md, README.md, TRACEABILITY.md, a requirement-linked change ledger, source and tests, initial failing output, final complete output, review findings, and an evidence-bounded completion statement.
