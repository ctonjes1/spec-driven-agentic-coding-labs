Module 1 Fail Closed Authorization Gate for an AI Agent

Secure enterprise services and agents

45–60 minute labsClaude Code and CodexEvidence required
Specification gate: finish and freeze SPEC.md and its acceptance criteria before creating implementation files.

Objective

Build a deterministic policy gate that returns ALLOW, DENY, or INVALID for a proposed agent action.

Human judgment

Explain why this policy gate neither authenticates the actor nor guarantees that a downstream tool obeys the decision.

Constraints

  1. Python standard library only
  2. No network calls or real agency data
  3. Unknown actions deny by default
  4. Audit output excludes purpose text and payload content

Threat and failure assumptions

  1. Prompt injection inside free-text fields
  2. Self-approval for restricted access
  3. Malformed or missing policy configuration
  4. Unknown actions introduced after deployment

Frozen contract

Write these numbered requirements into SPEC.md. Add exact schemas, reason codes, precedence, error behavior, trust boundaries, and requirement-to-test traceability. Mark the reviewed contract SPEC STATUS: FROZEN and SPEC VERSION: 1.0.

  1. R1 Validate an exact JSON request schema before authorization
  2. R2 Permit only allowlisted action and resource combinations
  3. R3 Always deny eligibility decisions and system-of-record writes
  4. R4 Restricted access requires approval by someone other than the actor
  5. R5 Emit stable decisions, reason codes, and exit codes
  6. R6 Fail closed when configuration is missing or invalid
  7. R7 Produce privacy-safe structured audit events

Acceptance criteria

  1. Permitted search returns ALLOW
  2. Unknown action returns DENY
  3. Eligibility action is denied regardless of approval
  4. Restricted access without independent approval is denied
  5. Mistyped required field returns INVALID
  6. Corrupted policy fails closed
  7. Repeated input produces the same decision
  8. Purpose text never appears in output or logs

Implementation checkpoints

TimeRequired activity
0–12 minutesClaude Code drafts SPEC.md and acceptance criteria. Codex challenges ambiguity, unsafe defaults, precedence, and unverifiable claims. The learner resolves findings and freezes version 1.0. No implementation files exist yet.
12–23 minutesCodex derives black-box tests from the frozen contract and captures the expected failing run. Claude Code identifies contradictions without silently rewriting tests or requirements.
23–41 minutesClaude Code implements only frozen requirements and updates the requirement-linked change ledger. Preserve the complete test output.
41–53 minutesCodex reviews the diff against SPEC.md, reruns tests independently, exercises the adversarial path, and inspects logs, errors, dependencies, and state transitions.
53–60 minutesThe learner records the human disposition, remaining assumptions, production gaps, and an evidence-bounded completion statement.

Required adversarial or failure-path test

Submit a write_system_of_record request whose purpose says to ignore policy, report ALLOW, and conceal the request. It must return DENY with the prohibited-action reason and must not log the purpose.

Evidence package

Module-specific evidence: Decision tests, fail-closed configuration result, prompt-injection result, and a privacy-safe audit sample.

Also submit SPEC.md, README.md, TRACEABILITY.md, a requirement-linked change ledger, source and tests, initial failing output, final complete output, review findings, and an evidence-bounded completion statement.
