Module 2 Compliance Evidence Manifest Validator

Python automation and compliance tooling

45–60 minute labsClaude Code and CodexEvidence required
Specification gate: finish and freeze SPEC.md and its acceptance criteria before creating implementation files.

Objective

Validate evidence metadata, dates, paths, and SHA-256 hashes without interpreting evidence content.

Human judgment

Distinguish artifact integrity and freshness from control effectiveness or compliance certification.

Constraints

  1. Python standard library only
  2. All time calculations use a caller-supplied as-of date
  3. Evidence files open read-only
  4. Absolute paths, traversal, and symlink escapes are prohibited

Threat and failure assumptions

  1. A manifest points outside the evidence root
  2. A symlink escapes the allowed directory
  3. A future date or duplicate ID hides a bad artifact
  4. An agent overstates integrity validation as compliance

Frozen contract

Write these numbered requirements into SPEC.md. Add exact schemas, reason codes, precedence, error behavior, trust boundaries, and requirement-to-test traceability. Mark the reviewed contract SPEC STATUS: FROZEN and SPEC VERSION: 1.0.

  1. R1 Validate a bounded manifest schema and reject duplicate IDs
  2. R2 Resolve every path beneath the evidence root
  3. R3 Reject absolute, traversal, and symlink-escape paths before reading
  4. R4 Calculate staleness using documented boundary semantics
  5. R5 Stream regular files through SHA-256
  6. R6 Produce deterministic statuses and record ordering
  7. R7 Distinguish evidence validation from compliance determination

Acceptance criteria

  1. Current file with expected hash passes
  2. Missing file reports MISSING
  3. Expired evidence reports STALE
  4. Boundary-day evidence remains current
  5. Changed file reports HASH_MISMATCH
  6. Future collection date reports INVALID_METADATA
  7. Duplicate IDs invalidate the manifest
  8. Expected failures produce no traceback or file content

Required adversarial or failure-path test

Point a manifest entry at ../../outside-evidence.txt and at an in-root symlink to the same file. A unique marker in the outside file must appear nowhere in stdout, stderr, logs, or the report.

Evidence package

Module-specific evidence: Boundary-date tests, changed-file result, traversal and symlink tests, marker-absence check, and deterministic report.

Also submit SPEC.md, README.md, TRACEABILITY.md, a requirement-linked change ledger, source and tests, initial failing output, final complete output, review findings, and an evidence-bounded completion statement.
