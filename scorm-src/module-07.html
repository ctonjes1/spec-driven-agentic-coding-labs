Module 7 Provenance Gated Memory Service for an Enterprise Agent

Secure enterprise services and agents

45–60 minute labsClaude Code and CodexEvidence required
Specification gate: finish and freeze SPEC.md and its acceptance criteria before creating implementation files.

Objective

Control which proposed memories become active and retrievable based on subject authorization, provenance, contradictions, and retention.

Human judgment

Distinguish memory admissibility from factual truth, consent, or decision authority.

Constraints

  1. Synthetic records only
  2. No model may approve its own memory
  3. Subject boundaries are mandatory
  4. Deletion and correction events remain auditable

Threat and failure assumptions

  1. Memory crosses subject boundaries
  2. A low-trust source overrides an authoritative source
  3. Contradictory claims become simultaneously active
  4. Expired or prohibited data remains retrievable

Frozen contract

Write these numbered requirements into SPEC.md. Add exact schemas, reason codes, precedence, error behavior, trust boundaries, and requirement-to-test traceability. Mark the reviewed contract SPEC STATUS: FROZEN and SPEC VERSION: 1.0.

  1. R1 Require subject, source, classification, observed time, and retention metadata
  2. R2 Reject prohibited classifications and unauthorized subjects
  3. R3 Quarantine contradictions pending review
  4. R4 Supersede rather than silently overwrite active memories
  5. R5 Filter retrieval by subject, authorization, status, and expiry
  6. R6 Preserve lineage across correction and deletion events
  7. R7 Emit metadata-only audit events

Acceptance criteria

  1. Authorized admissible memory becomes active
  2. Cross-subject proposal is denied
  3. Prohibited classification is denied
  4. Contradiction is quarantined
  5. Correction supersedes with lineage
  6. Expired memory is not retrieved
  7. Deleted memory is not retrieved
  8. Audit output excludes memory text

Required adversarial or failure-path test

Propose a confidential memory for another subject and mark it as more authoritative than an existing record. The service must deny it before storage and must not echo the text in logs.

Evidence package

Module-specific evidence: Subject-isolation tests, prohibited-classification result, contradiction quarantine, supersession history, and retrieval-filter tests.

Also submit SPEC.md, README.md, TRACEABILITY.md, a requirement-linked change ledger, source and tests, initial failing output, final complete output, review findings, and an evidence-bounded completion statement.
