Module 9 Hybrid Azure Deployment Preflight Gate

.NET and Azure production systems

45–60 minute labsClaude Code and CodexEvidence required
Specification gate: finish and freeze SPEC.md and its acceptance criteria before creating implementation files.

Objective

Evaluate a synthetic Azure deployment request against placement, cost, tagging, networking, identity, and diagnostics policy.

Human judgment

Separate preflight readiness from pricing accuracy, deployment approval, and Azure Policy enforcement.

Constraints

  1. No Azure deployment
  2. Use a frozen synthetic SKU catalog
  3. Calculate maximum monthly cost
  4. Exceptions have narrow scope and expiry

Threat and failure assumptions

  1. A corrupted catalog yields an artificially low estimate
  2. An exception bypasses unrelated policies
  3. Missing diagnostics or private networking is ignored
  4. A request claims approval based on preflight success

Frozen contract

Write these numbered requirements into SPEC.md. Add exact schemas, reason codes, precedence, error behavior, trust boundaries, and requirement-to-test traceability. Mark the reviewed contract SPEC STATUS: FROZEN and SPEC VERSION: 1.0.

  1. R1 Validate request and policy catalog versions
  2. R2 Require approved region, tags, identity, diagnostics, and network posture
  3. R3 Calculate maximum monthly cost with explicit units and rounding
  4. R4 Deny when the catalog is missing, corrupt, or untrusted
  5. R5 Bind exceptions to policy ID, resource, approver, and expiry
  6. R6 Return deterministic findings and overall status
  7. R7 Log metadata without secrets or template content

Acceptance criteria

  1. Compliant request passes preflight
  2. Missing required tag fails
  3. Public network posture fails
  4. Missing diagnostics fails
  5. Budget boundary is handled exactly
  6. Over-budget request fails
  7. Corrupted catalog fails closed
  8. Exception cannot waive an unrelated policy

Implementation checkpoints

TimeRequired activity
0–12 minutesClaude Code drafts SPEC.md and acceptance criteria. Codex challenges ambiguity, unsafe defaults, precedence, and unverifiable claims. The learner resolves findings and freezes version 1.0. No implementation files exist yet.
12–23 minutesCodex derives black-box tests from the frozen contract and captures the expected failing run. Claude Code identifies contradictions without silently rewriting tests or requirements.
23–41 minutesClaude Code implements only frozen requirements and updates the requirement-linked change ledger. Preserve the complete test output.
41–53 minutesCodex reviews the diff against SPEC.md, reruns tests independently, exercises the adversarial path, and inspects logs, errors, dependencies, and state transitions.
53–60 minutesThe learner records the human disposition, remaining assumptions, production gaps, and an evidence-bounded completion statement.

Required adversarial or failure-path test

Supply a catalog with a missing price and an exception for tagging, then request public networking and no diagnostics. The gate must fail closed and the tagging exception must not affect other findings.

Evidence package

Module-specific evidence: Independent cost calculation, budget-boundary tests, corrupted-catalog result, exception-bypass test, and dependency inspection.

Also submit SPEC.md, README.md, TRACEABILITY.md, a requirement-linked change ledger, source and tests, initial failing output, final complete output, review findings, and an evidence-bounded completion statement.
