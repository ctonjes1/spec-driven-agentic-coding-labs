Module 11 Nonstandard SaaS Exception Readiness Validator

Python automation and compliance tooling

45–60 minute labsClaude Code and CodexEvidence required
Specification gate: finish and freeze SPEC.md and its acceptance criteria before creating implementation files.

Objective

Determine whether a nonstandard platform request is complete enough for architecture review using five-year cost, ownership, evidence, and exit requirements.

Human judgment

Distinguish a complete exception packet from technical suitability, approval authority, or a procurement recommendation.

Constraints

  1. Python standard library only
  2. Synthetic vendor and cost data
  3. Exactly five cost years are required
  4. The validator makes no procurement recommendation

Threat and failure assumptions

  1. A zero-cost year hides migration or support cost
  2. Narrative claims substitute for evidence
  3. Ownership is assigned to an unavailable team
  4. Exit and data portability remain undefined

Frozen contract

Write these numbered requirements into SPEC.md. Add exact schemas, reason codes, precedence, error behavior, trust boundaries, and requirement-to-test traceability. Mark the reviewed contract SPEC STATUS: FROZEN and SPEC VERSION: 1.0.

  1. R1 Validate identity, sponsor, owner, use, data, integration, and contract metadata
  2. R2 Require five explicit annual cost records and calculate total cost
  3. R3 Require evidence for security, accessibility, records, and architecture claims
  4. R4 Flag missing operational ownership and support model
  5. R5 Require export format, retention, deletion, and exit cost
  6. R6 Produce deterministic blockers, warnings, and input hashes
  7. R7 State that readiness does not equal suitability or approval

Acceptance criteria

  1. Complete request produces READY_FOR_REVIEW
  2. Missing year is a blocker
  3. Zero-cost year requires documented justification
  4. Missing owner is a blocker
  5. Unsupported claim is a blocker
  6. Missing portability or exit plan is a blocker
  7. Independent five-year total matches
  8. Narrative text never appears in logs

Implementation checkpoints

TimeRequired activity
0–12 minutesClaude Code drafts SPEC.md and acceptance criteria. Codex challenges ambiguity, unsafe defaults, precedence, and unverifiable claims. The learner resolves findings and freezes version 1.0. No implementation files exist yet.
12–23 minutesCodex derives black-box tests from the frozen contract and captures the expected failing run. Claude Code identifies contradictions without silently rewriting tests or requirements.
23–41 minutesClaude Code implements only frozen requirements and updates the requirement-linked change ledger. Preserve the complete test output.
41–53 minutesCodex reviews the diff against SPEC.md, reruns tests independently, exercises the adversarial path, and inspects logs, errors, dependencies, and state transitions.
53–60 minutesThe learner records the human disposition, remaining assumptions, production gaps, and an evidence-bounded completion statement.

Required adversarial or failure-path test

Omit year five, claim security compliance without evidence, provide no operational owner, and state that exit costs are zero without justification. The validator must return NOT_READY with separate blockers.

Evidence package

Module-specific evidence: Independent five-year TCO check, missing-year and zero-cost tests, portability and exit findings, input hashes, and narrative-leakage inspection.

Also submit SPEC.md, README.md, TRACEABILITY.md, a requirement-linked change ledger, source and tests, initial failing output, final complete output, review findings, and an evidence-bounded completion statement.

Common review rubric

CategoryPointsFull credit standard
Specification fidelity20Every behavior traces to a frozen requirement.
Correctness20Valid and invalid paths produce deterministic documented outcomes.
Testing15Acceptance, boundary, adversarial, and failure paths are demonstrated.
Security15The solution fails closed, protects sensitive content, and constrains authority.
Maintainability10The design is small, explicit, and free of speculative abstraction.
Observability10Reason codes, state changes, and preserved evidence support review.
Human judgment10Claims stay within the evidence and production gaps are explicit.

Passing standard: 85 points, with at least 12 of 15 in both Testing and Security. Missing frozen specification, adversarial evidence, or evidence-bounded completion statement prevents a passing result.

Knowledge check and evidence attestation

2. How many cost years are required?
3. What should a zero-cost year require?
4. What exit information belongs in the packet?
